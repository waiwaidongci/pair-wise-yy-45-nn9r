# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 供应商现场断网 → 重连同步 → 快照锁定

评审员在供应商现场网络不稳定，系统按以下规则保证数据不丢、不重、不被悄悄覆盖：

1. **断网就地记录，刷新不丢**：断网（可点侧栏「模拟断网」复现）时新增批注、批注关闭、方案决定都进入本机持久化待处理队列（localStorage），页面刷新后仍在，并以乐观视图显示。
2. **重连即同步**：监听 `online/offline` 事件，重连后先拉最新数据再按 FIFO 自动冲刷队列，也可在同步中心手动触发。
3. **补交多次不会变两份**：每条记录生成时携带 `X-Client-Id` 幂等键，服务器对相同幂等键只处理一次并回放首次结果；重试、重复补交不会产生重复批注/决定。
4. **服务器版本更新时不覆盖**：每条记录带 `baseVersion` 乐观锁。服务器已有更新版本时返回 `409` 和冲突明细（服务器改了什么 vs 本地待处理项），本地项保留在队列中标红，由评审员「重新核对并重放」或「丢弃本地项」，系统绝不自动覆盖。
5. **锁定门槛**：审核锁定要求在线、待处理队列清空（含未决冲突）、无待处理批注/待决定方案，且本地版本与服务器一致。快照过期时服务器以 `snapshot_stale` 拒绝锁定并要求重新核对。
6. **快照同源**：锁定在服务器生成不可变快照（冻结整份样衣 + checksum 校验和）。锁定后总览、历史页、JSON 导出读的是同一份快照，页面只读。
7. **解锁后旧快照仍可查**：解锁开启新的修订分支，旧快照标记为「历史快照」保留，随时可在历史页查阅与导出（导出时重新校验 checksum）。

侧栏「同步中心」可查看队列状态、每条幂等键与冲突明细；评审页「模拟远端更新」按钮可复现另一台设备先提交导致的版本冲突。

## 行为验证

```bash
npm run verify         # 服务端 30 项 + 客户端 27 项断言
npm run verify:server  # 幂等 / 409 / 锁定 / 快照同源 / 解锁保留
npm run verify:client  # 离线入队 / 持久化 / 重连同步 / 冲突重放 / 锁定门槛
```
